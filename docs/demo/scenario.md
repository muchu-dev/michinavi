# デモシナリオと通し確認

対象タスク: FE-21（デモシナリオの通し確認）／ CO-03（デモシナリオを決める）／ CO-07（通し動作確認）

台本の本体は `apps/frontend/src/config/demo-scenario.ts` にある。
文章だけで持つと画面の増減に気づけないので、手順を配列で持ち、
行き先の画面が実在すること・投稿を見せる手順が投稿を読む画面を向いていることを
テストで検査している（`demo-scenario.test.tsx`）。台本を直すときは
`demo-scenario.ts` とこのファイルの両方を直す。

書いてあるのは、いまの `main` の画面で実際にできる操作だけである。
まだ画面に無いものは手順から外し、「今日は触れない」として明記した。

持ち時間は 5 分。手順は 5 つで、1 手順あたり 1 分を目安にする。

## 準備

1. `pnpm install`
2. `pnpm db:start` でローカルの Supabase を起動する
3. `pnpm db:reset` で `packages/db/supabase/seed.sql` を流す
   （地区と、真備町の架空の避難所 5 件がここで入る）
4. `pnpm demo:seed` でデモ用の家族と投稿を入れる
   （BE-26。3 世帯・7 人・投稿 12 件。何度実行しても同じ状態になる）
5. `pnpm dev` でアプリを起動する
6. `/login` から `demo-sato@michinavi.example` / `demo-password-1234` でログインする
   （`pnpm demo:seed` の出力にも 3 世帯分のログイン情報が出る）
7. **ブラウザの位置情報をデモ位置に固定する。**
   Chrome なら DevTools の Sensors で Location を「Other…」にし、
   緯度 `34.6383` / 経度 `133.6903`（倉敷市真備町箭田）を入れる

手順 7 は飛ばさない。投稿タブは見ている場所の 2 次メッシュ（`513375`）で
投稿を絞り込むため、位置情報が真備町から外れると、シードした投稿が
一覧からも地図からも消える。投稿するボタンも現在地が取れるまで押せない。

すべてのデモ用データは架空である。アカウントの表示名は「デモ」で始まり、
メールアドレスは予約済みの `michinavi.example`、避難所も実在の施設ではない。

## 通し確認のやり方

1. 上の準備を済ませる
2. `/demo` を開く（ナビゲーションには出ない。URL を直接開く）
3. 手順 1 から順に「この画面を開く」で移動し、台本どおりに操作する
4. 詰まらずに通れた手順にチェックを入れる
5. 5 つすべてにチェックが付いたら一周できたことになる

チェックの記録はその端末に残る。発表者が変わるときは「確認の記録を消す」から始める。

投稿は通し確認のたびに増える。地図が濃くなりすぎたら `pnpm demo:seed` を
流し直すと元の 12 件へ戻る。

## 台本

| 手順 | 画面 | 操作 | 話すこと |
| --- | --- | --- | --- |
| 1 | `/posts` | 件数付きのピンと左下の凡例（通行可・注意・通行不可）を指す | 最初に知りたいのは「いま、その道が通れるか」 |
| 2 | `/posts` | 「現在地を追跡」→「この道の状況を報告する」→ 通れない・冠水・投稿する | 一次情報は住民しか持っていない。文章を書かせない |
| 3 | `/posts` | 戻った地図で、同じ地点のピン（件数が1つ増えて赤）を開く | 同じ場所の投稿は1つの吹き出しにまとまる |
| 4 | `/evacuation` | 避難経路タブで「デモ位置」→「選択肢を作る」→ 1件開いて切り替え基準まで読む → 避難所タブで「デモ位置」→ 1件開く | 指示はしない。取りうる選択肢と、切り替えの基準を出す。決めるのは本人 |
| 5 | `/family` | 3人が「未確認」で並ぶ → 自分を「避難済み」→ 配偶者に「支援が必要と伝える」 | 地図は出さない。無事かどうかだけ共有する |

各手順の「必要な準備」「今日は触れない」「詰まったとき」は `/demo` の画面に出る。

手順 2 で送る投稿は、デモ位置と同じメッシュ（`5133756531`）に乗る。
そこにはシード済みの投稿が 3 件あるので、手順 3 でピンの件数が 3 から 4 へ増え、
最新の投稿が「通れない」になったぶん色が赤へ変わる。

## 手順 4 で画面に出るもの

`/evacuation` は #50（FE-14）で入れ替わった。避難経路タブは、上半分が地図、
その下が「デモ位置 / 現在地」の切り替え、下半分が避難の選択肢（`ChoicePanel`）である。

- **初回は必ず「避難の選択肢はまだありません」から始まる。**
  `evacuation.latest` が `NOT_FOUND` を返すためで、`pnpm demo:seed` は
  提案を作らない。ここに出る「選択肢を作る」を押して `evacuation.generate` を走らせる
- 生成後は「AIが提案する避難の選択肢」という見出しと、その横に「更新」、
  右端に「◯件/HH:MM時点」が出る。選択肢のカードは推奨順で、1 件目に「推奨」が付く
- カードを開くと、理由・避難先・**注意点**・**切り替えを考える目安**が出る。
  デモ佐藤家（大人 2 人・子 1 人・車 1 台、移動に配慮が必要な家族なし）では
  「徒歩で避難する」「車で避難する」「自宅にとどまる」の 3 件になる。
  自宅周辺に「通れない」の推定があるときは「建物の上階へ移る」が加わって 4 件になり、
  並びも「自宅にとどまる」が先頭へ変わる。**件数は言い切らない**
- 避難先の名前（「混雑状況を考慮した避難先：…」）は `shelterAssignment.assign` の
  結果なので、**先に避難経路タブの「デモ位置」を押しておく**こと。押していないと
  「避難先未選択」と出る
- 所要時間はサーバがまだ持っていない（`estimatedMinutes` は常に null）。
  徒歩の選択肢に出るのは「直線距離での目安 約◯分」で、画面にもそう書いてある

`GEMINI_API_KEY` が無くても選択肢は出る。サーバが決定論的に候補を作り、
AI には並び順と文面だけを任せる作りで、AI が使えないときは定型の文面がそのまま入る。

**2 周目以降は「選択肢を作る」が出ない。** 一度作った提案が残るため、
`evacuation.latest` が最新の提案を返して一覧から始まる。本番前の通し確認で
「選択肢を作る」の絵を出したいときは `pnpm demo:seed` を流し直す
（デモ用アカウントごと作り直すので、そのアカウントの提案も消える）。
一覧から始まった場合は、見出し横の「更新」で作り直して同じ話をする。
提案は 180 分で古くなり、そのときは「この情報は古くなっています」が上に出る。

## 今日は見せないもの

台本から外した。聞かれたら「まだ画面に無い」と答える。

- **地図タブ（`/`）**: 投稿を取りに行かない固定のサンプル表示のままである。
  投稿を地図へ出しているのは投稿タブだけなので、手順 1〜3 はそちらで通す。
  地図タブが投稿を出すようになったら、手順 1 と 3 の行き先を戻す。
- **投稿の原因（冠水・土砂など）**: 画面では選べるが、まだ保存していない。
  保存されるのは通行状態と投稿地点のメッシュだけで、画面にもその断りが出る。
- **地図の吹き出しの道路状況の推定**: 一度 #46 で入れたが #51 で revert した。
  吹き出しに出るのは「◯件の投稿」と各投稿の一覧だけで、推定は出ない。
  地図のピンの色は、同じ地点の最新の投稿そのものから決めている。
  推定（`road_status_estimates`）は投稿のたびに裏で作り続けており、
  手順 4 の選択肢カードの下に「周辺に注意情報あり・投稿◯件」という
  集計の形でだけ現れる。地図の吹き出しの話とは混ぜない。
- **避難の選択肢の所要時間**: 選択肢と切り替え基準そのものは #50 で画面に入ったが、
  所要時間はサーバがまだ返さない（BE-14 / BE-20 待ち）。徒歩の選択肢に出る分数は
  避難先までの直線距離を 80m/分で割った目安である。道のりの時間として話さない。
- **安否の共有範囲と履歴**: 家族タブは #44 で実データにつながり、`pnpm demo:seed`
  で作ったデモ佐藤家の 3 人が出る。ただし「誰に見せるか」の設定
  （`memberStatus.setShareScope`）と安否の履歴（`memberStatus.history`）は
  API にはあるが画面に無い。
- **投稿の通報のその先**: 投稿の吹き出しから「この投稿を通報する」を送れるが
  （#22）、運営が見る画面はまだ無い。手順 3 では押さない。

- 投稿タブの地図が 0 件になった: 位置情報が真備町から外れている。
  DevTools の Location を `34.6383` / `133.6903` に戻して再読み込みする
