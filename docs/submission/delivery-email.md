## 本文

```
お世話になっております。チーム ムチュウです。
最終発表会に向けた納品物を提出いたします。

■ チーム名
ムチュウ

■ チームメンバー
★ 氏名を記載（例：山田 太郎 / 佐藤 花子 / …）

■ プロダクト名
michinavi（ミチナビ）

■ プロダクトURL
https://michinavi.vercel.app

■ プレゼン動画URL
★ 動画のURLを記載（ログイン不要で視聴できる状態にしてください）

■ プロダクトのコンセプト
災害時に本当に知りたいのは、天気でも避難所の場所でもなく「いま、目の前の道が
通れるか」です。その情報を持っているのは、現場にいる住民自身です。

みちナビは、住民が3タップで投稿した通行可否を地図に集め、そこから避難の判断
材料を返すアプリです。

AIは「避難してください」とは言いません。自宅にとどまる・徒歩・車という複数の
選択肢を根拠つきで並べ、「どうなったら切り替えるか」の基準まで示します。
決めるのは本人である、という立場を出力の形そのものに埋め込みました。

■ 機能紹介（審査時に実際に操作できるもの）
1. ログインと平常時の登録
   家族構成・自宅・車の有無を登録しておき、災害の当日は開くだけにしています。

2. 地図
   対象地域（岡山県倉敷市真備町）を表示し、通れる／注意／通れない を3色で
   示します。現在地の表示にも対応しています。

3. 投稿と、地点ごとの集約表示
   「通れる／注意／通れない」を選ぶだけの3タップで投稿できます。文章の入力は
   必須にしていません。投稿は250mメッシュ単位でまとめられ、地図には
   「その地点に何件の報告が集まっているか」が色と数字で出ます。
   審査用アカウントでは12件の投稿が6地点にまとまった状態でご覧いただけます。

4. 家族の状況
   「避難済み」「支援が必要」を家族に共有します。地図は出しません。

■ サーバ側は実装済みで、画面への接続が残っているもの
以下はAPIとして動作し、自動テストもありますが、今回の提出時点では画面から
操作できません。プレゼン動画では設計の考え方としてご説明しています。

・避難の選択肢と切り替え基準の生成（家族構成・車の有無・周辺の投稿から生成）
・避難所の検索（ペット同行・車いすなどの受入条件つき）と、定員超過時の分散
・AIによる道路状態の推定と、地点ごとの要約
・写真の添付とExif（位置情報）のサーバ側での削除
・不適切な投稿の通報と、運営による非表示
・メッシュ単位の経路提案

■ デザイン紹介
・災害時に片手で、急いで操作する前提で設計しました。タップ領域は44px以上、
  主要なボタンは親指の届く画面下部に置いています。
・色は5色以内に絞りました（基本の青／通れる緑／注意の黄／通れない赤／文字の黒）。
・赤と緑が区別しにくい方に配慮し、色だけで意味を伝えないようにしています。
  地図のピンは色と件数の数字、凡例は色と文字を併記します。
・「まだ投稿がありません」で終わらせず、次に何をすればよいかを必ず書いています。

■ その他アピールポイント
1. AIに選択肢そのものを作らせていません
   候補はサーバ側が決めます（車のない世帯に「車」の選択肢が出ることは、仕組みの
   上で起こりません）。AIに任せるのは並び順・文面・切り替え基準だけで、出力は
   候補集合と突き合わせて検証し、1つでも合わなければ全部捨てて決定論的な選択肢に
   戻します。AIが落ちても選択肢は出ます。

2. 「緊急時に、こんなアプリを触れるのか」への答え
   揺れている最中や水が迫っている瞬間には触れません。そこは認めたうえで、
   みちナビが狙うのは「避難指示が出てから避難を終えるまでの数時間」、つまり
   行くか留まるかを決める時間帯です。そのために、
   ・当日の操作を3タップに削り、登録は平常時に済ませる設計にしました
   ・アカウントを持たない家族（高齢の親、子ども）の安否は、同居する家族が
     代理で登録できるようにしました
   今後は、通知からのワンタップ応答や音声入力など「触らせない」方向に
   伸ばしていく想定です。

3. 位置情報を丸めて保存しています
   投稿位置は約250mのメッシュに丸めてから保存し、生の座標はどこにも残しません。
   写真のExif（位置情報）はサーバ側で削除してから保存します。

4. 他人のデータが取れないことをテストで固定しています
   全テーブルで行レベルセキュリティを有効にし、他人のIDを指定しても0件になる
   ことを自動テストで担保しています。テーブルを追加したときに、公開してよいか
   の判断を通らずに公開されることがない作りにしました。

5. APIが落ちたときの案内を、エラー応答そのものに載せています
   画面ごとに書き忘れることがないよう、サーバ側の障害時は行政（倉敷市）と
   気象庁への案内を必ず添えて返します。

■ 今後の展望
・混雑状況の可視化：現時点では実測する手段がなく、データを持っていません。
  住民の投稿から推定する以外の材料（自治体・通信事業者のデータなど）が必要だと
  考えています。
・実在の避難所データの取り込み：取り込みの仕組みは実装済みで、現在は架空の
  5施設が入っています。公開データが揃い次第そのまま差し替えられます。
・気象庁の警戒情報との連動：切り替え基準の「警戒レベル4」を、実際の発表と
  突き合わせて自動で状態を変える。
・画面への接続：上記の「サーバ側は実装済み」の各機能。

■ 審査時の注意事項・動作環境
・推奨環境：スマートフォンの縦画面（Chrome / Safari の最新版）。
  PCの場合はブラウザの幅を狭めるか、開発者ツールのモバイル表示でご覧ください。
・ログインが必要です。下記の審査用アカウントをお使いください。

  メールアドレス：demo-sato@michinavi.example
  パスワード　　：demo-password-1234

  （家族が3人の世帯の例です。ほかに demo-tanaka@michinavi.example、
    demo-suzuki@michinavi.example も同じパスワードでご利用いただけます）

・投稿の集約表示は「投稿」タブでご確認ください。地図タブは地域の表示のみです。
・地図に表示される投稿、避難所、家族はすべて架空のデータです。実在の施設・
  人物ではありません。
・位置情報の許可を求める場面がありますが、許可しなくても操作できます。
・「避難計画」タブは画面の実装が間に合わず、準備中の表示になっています。

以上、よろしくお願いいたします。

チーム ムチュウ
```
